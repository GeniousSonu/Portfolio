# Incident Report: INC-001 — Blank Page After Some Use

**Severity:** Critical (P0)  
**Status:** Root Cause Identified · Defense in Depth Implementation Active  
**Date:** 2026-10-13  
**Authors:** Senior Infrastructure & Frontend Engineering  
**Branch:** `fix/inc-001-blank-page`  

---

## 1. Executive Summary & Symptoms

Visitors navigating the portfolio experience a complete blank page where only the viewport scrollbar and background color (`#050505`) render. No text, images, or interactive elements are visible. Normal page reloads (`F5` or `Cmd+R`) do not restore the site, leaving users permanently stuck in the broken state across reloads and browser sessions.

---

## 2. Root Cause Analysis (Confirmed with Evidence)

Through systematic investigation of delivery configuration, service worker caching, CSS rules, React hydration, and browser storage, the blank screen was reproduced and attributed to a cascade of four interrelated architectural flaws:

### Primary Trigger (H1): Stale Service Worker Navigation Cache Serving Dead Chunks
- **Location:** `public/sw.js` (Strategy A, lines 70–101)
- **Mechanism:** `public/sw.js` implemented a `Stale-While-Revalidate` cache (`sks-pages-${CACHE_VERSION}`) for all navigation requests (`request.mode === 'navigate' || request.headers.get('accept')?.includes('text/html')`).
- **The Failure Cascade:**
  1. User visits Version A of the site. `sw.js` caches the raw HTML document of `/` into `sks-pages-v-...`.
  2. A new version (Version B) of the portfolio is deployed. In Next.js, script chunks receive new content hashes (`/_next/static/chunks/app/page-[new-hash].js`). Old chunk files are deleted on the host/CDN.
  3. User returns to the site or reloads. The service worker intercepts the navigation request and **immediately returns the cached Version A HTML**.
  4. The browser begins parsing Version A HTML and requests old script chunks (`page-[old-hash].js`).
  5. The server returns HTTP 404 (or HTML fallback) for the missing old chunks.
  6. The browser throws `ChunkLoadError: Loading chunk ... failed`.
  7. Because `sw.js` intercepts all subsequent navigation requests, a normal refresh serves the stale Version A HTML again and again. The user cannot escape without manually unregistering service workers and clearing Cache Storage in DevTools.

### Secondary Trigger (H3): Content Hidden by Default in Static CSS
- **Location:** `src/app/globals.css` (lines 661, 681, 687, 692, 696, 702, 707, 1785–1788)
- **Mechanism:** Core layout and typography elements were hardcoded in CSS with `opacity: 0` and offscreen translations:
  - `.hero-name-line span { opacity: 0; transform: translateY(110%); }`
  - `.hero-role { opacity: 0; transform: translateY(20px); }`
  - `.hero-desc { opacity: 0; transform: translateY(20px); }`
  - `.hero-actions { opacity: 0; transform: translateY(20px); }`
  - `.hero-terminal { opacity: 0; transform: translateY(30px); }`
  - `.hero-stats { opacity: 0; transform: translateY(20px); }`
  - `.reveal { opacity: 0; transform: translateY(40px); }`
  - `.reveal-left, .reveal-right, .stagger-child { opacity: 0; }`
- **Result:** Because `ChunkLoadError` aborted React hydration, GSAP entrance animations never executed. The DOM retained full document height (producing the scrollbar), but every headline, sentence, button, and card remained rendered at `opacity: 0` against the `#050505` background.

### Tertiary Factor (H2 & H4): Complete Absence of React Error Boundaries
- **Location:** `src/app/`
- **Mechanism:** Neither `src/app/error.js` nor `src/app/global-error.js` existed in the codebase.
- **Result:** Any unhandled rejection during hydration or chunk load crashed the entire React tree down to the root document. React unmounted or failed to paint fallback UI, producing a void canvas.

### Contributing Factor (H8): Missing No-Cache Directives on HTML Deliveries
- **Location:** `next.config.mjs`
- **Mechanism:** While `next.config.mjs` configured cache headers for fonts and `/sw.js`, HTML documents lacked explicit `Cache-Control: public, max-age=0, must-revalidate` response headers.

## 4. Defense-in-Depth Implementation Plan (Phase B)

1. **Service Worker Architecture Overhaul:**
   - Eliminate HTML navigation caching in `sw.js` entirely. Navigation requests are strictly Network-First or Network-Only with an offline fallback page.
   - Never cache `/api/*`, `/studio/*`, `_rsc` query parameters, or POST requests.
   - Only cache immutable `/_next/static/` assets and verified static assets.
   - On SW activation, purge all previous caches and unfamiliar cache buckets.
   - Serve `/sw.js` with `Cache-Control: no-cache, no-store, must-revalidate`.
2. **Client Self-Healing Recovery Module:**
   - Global handler for `ChunkLoadError`, `"Loading chunk failed"`, and chunk dynamic import rejections.
   - Unregisters service workers, empties Cache Storage, sets a single-recovery session guard, and reloads automatically.
3. **Emergency Kill-Switch Route (`/reset`):**
   - Uncached route at `/reset` that nukes all service worker registrations, Cache Storage buckets, and app storage keys, then redirects cleanly to `/`.
4. **React Error Boundaries:**
   - Add `src/app/error.js` and `src/app/global-error.js` providing graceful, dependency-free UI recovery with "Reload" and "Reset Site Cache" options.
5. **Content Visible by Default (Failsafe Class):**
   - Invert CSS initial states: all content is visible by default (`opacity: 1`).
   - Hidden animation states are applied only when an inline script confirms JavaScript is active (`html.js-motion`).
   - Add a 3-second failsafe timer removing motion classes if animation reveals fail to execute.
6. **Preloader Hardening:**
   - Enforce an absolute 4-second maximum duration ceiling.
   - Safe unmount guarantees: always release `.preloader-locked` and body overflow even on animation throw.
   - Support `pageshow` with `persisted = true` (bfcache).
7. **Storage Hardening (`safeStorage` helper):**
   - Central utility with try/catch, schema validation, and fallback for all storage operations.
8. **Scroll Lock & Lenis Stack:**
   - Stack-based scroll lock with automatic release on route change, unmount, and page visibility changes.
9. **View Transitions Safety:**
   - Safe wrapper around `document.startViewTransition` with 450ms timeout guard and CSS cleanup.
10. **Startup Resilience:**
    - Lazy, try/catch protected initialization for Firebase, analytics, and third-party scripts.
11. **HTTP Cache Headers:**
    - Explicit `Cache-Control: public, max-age=0, must-revalidate` for all HTML documents in `next.config.mjs`.
